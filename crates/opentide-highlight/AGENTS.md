# opentide-highlight — agent guide

The frozen HighlightSpec (`highlights/spec.toml`), semantic-token encoding, the generated editor
maps (TextMate, Monaco, Helix under `highlights/generated/`), Markdown and HTML rendering of
tokens, and the Tide field catalog the editor reads (`data/catalogs/tide/generated/fields.json`,
compiled in, or a workspace's catalog installed at run time).

## Place

foundation, tier 1: depends on opentide-core. Every query engine, opentide-tide,
opentide-analysis, opentide-lsp and opentide-wasm depend on it.

## Invariants

- Renaming a capture is a major (breaking) change; adding one is a minor (`[meta].version`).
- `highlights/generated/` is written by `opentide-lsp generate-highlights`, never by hand.
- The bundled Tide catalog is generated from `src/opentide` (`scripts/engine/sync_opentide_schemas.py`) and checked by `tests/test_generation/test_bundled_tide_catalog.py`.
- A workspace catalog replaces the bundled one process-wide, so `tests/workspace_catalog.rs` is a binary of its own.
- No `std::fs` in `src/`.

## Test

```bash
cargo nextest run --profile fast -p opentide-highlight
cargo run -p opentide-lsp -- generate-highlights --check
uv run pytest tests/test_generation/test_bundled_tide_catalog.py --no-cov -q
```

## Do not

- Edit `highlights/generated/` or `data/catalogs/tide/generated/` by hand.
- Rename a capture to fit a theme.
