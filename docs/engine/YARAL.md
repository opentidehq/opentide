# YARA-L

The YARA-L engine (`crates/opentide-yaral`) checks YARA-L 2.0, the detection and search language of Google Security Operations, as [yara-l-1.0](https://github.com/opentidehq/specifications/blob/main/specs/languages/yara-l-1.0.md) defines it, for the Google SecOps platform ([google-secops-1.0](https://github.com/opentidehq/specifications/blob/main/specs/platforms/google-secops-1.0.md)). Design: [RFC 0017 §7](https://github.com/opentidehq/specifications/blob/main/rfcs/0017-google-secops-yara-l.md#7-analysis-engine-language-server).

Language id `yaral` (`.yaral`, Google's community convention, and `.yl2`); TextMate scope `source.yaral` (Google's own VS Code grammar is `source.yara-l`, so both can be installed). Platform: Google SecOps (`configurations.google_secops`, and hunts with `system: google_secops`).

YARA-L shares its name and little else with [YARA](YARA.md): no code, catalogue or grammar is shared.

## No offline compiler

Google publishes no grammar, no compiler and no reference parser. The engine is an offline approximation: it reports what Google's pages say the compiler refuses and never claims a compile. The tenant's compiler, `verifyRuleText`, is the live check (`opentide validate query --live`), and `scripts/oracles/README.md` describes the opt-in tenant job. An offline result is never reported as a tenant check.

## Pipeline

1. **Grammar** (`grammars/tree-sitter-opentide-yaral`): written for yara-l-1.0 from Google's syntax pages: rules with every section (`setup` and `export` included) in any order, hop, tumbling and sliding windows, `!` terms, `#` counts, map keys, `%list` and `%table.column`, regexes with `nocase`, double-quoted and back-quoted strings, namespaced functions, `if(...)`, `any`/`all`, `N of [...]`, and the search form: bare UDM paths, an optional `events:` label, `dedup`, `order`, `limit`, `select`, `unselect` and `stage <name> { }`. Keywords are spelled lower, upper or title case (`and`, `AND`, `And`), the forms Google's rules use. Its errors are `yaral_parse_error`. It parses all 410 rules of chronicle/detection-rules' `rules/community` and every rule example of Google's YARA-L pages but placeholders (`...`, `<some window>`).
2. **Checker** (`check.rs`): sections and their order for the profile, scope (event variables, placeholders, outcome variables, stages), `match`, `outcome`, `condition`, `options`, the UDM and function catalogues, literals and limits.

A text is a **rule** (`rule` profile) when it holds a `rule` declaration, else a **search**. A Google SecOps block's sections are always a rule; a hunt is always a search.

## Catalogues

| Path | Contents |
|------|----------|
| `catalogs/yaral/udm.toml` | The Unified Data Model as a type graph: every message of the event model, the entity model (under `graph`) and the detection model (the Chronicle API `Collection`, under `detection`), each field with its type, `repeated`, `enum` and `deprecated`, and every enumerated type's values |
| `catalogs/yaral/functions.toml` | Every function of Google's YARA-L function list, the `metrics.*` functions, and the outcome aggregations: namespace, signature, arity, parameter and result types, availability (`rules`, `search`, `dashboards`) and Google's first sentence |

Both are generated by `scripts/sync_yaral_catalogs.py` from Google's pages (CC BY 4.0, `catalogs/yaral/NOTICE`); never hand-edit them. The UDM is a graph, not a path list, because it recurses (`Process.parent_process` is a `Process`). Where the pages are wrong the script corrects them, each with its evidence: the Markdown export spells `registry_key` as `registry*key*`, the field list labels the `attribute` message "(Enumerated list)", and `strings.split` and `window.median` take an optional second argument their signature line does not mark.

Reference lists, data tables and their columns, composite producer names and curated rules live in the tenant: they are never reported unknown. Keys under a map index or under a `google.protobuf.Struct` (`additional.fields["k"]`) are free.

## Codes

Errors are what Google's compiler refuses. **Page** is Google's page the check follows (`https://cloud.google.com/chronicle/docs/` + path). **Test** names the case in `crates/opentide-yaral/tests/codes.rs` (the function of the code's name), `crates/opentide-tide/tests/google_secops.rs` (block), or a unit test.

## In Tide objects

| Path | Analysed as |
|------|-------------|
| `configurations.google_secops.{setup,events,outcome,condition,export}` | One injection: the rule deploy assembles, `rule` profile |
| `configurations.google_secops.{match,options}` | YAML, checked by the block; rendered into the assembled rule |
| `response.procedure.searches[].query` with `system: google_secops` | A search, `search` profile |

The assembled rule is google-secops-1.0's "Assembled rule": `rule <name> {`, a generated `meta:`, then each section present in order, its label indented two spaces and its lines four, one blank line before each. `crates/opentide-tide/tests/google_secops.rs` `the_assembled_rule_matches_the_golden_text_line_for_line` compares it with the spec's golden `.yaral` texts from `events:` on. The section texts map back byte for byte: a finding on line `n` of a section is on line `L + n` of the rule, four columns to the right, and lands on its own line and column in the YAML. The header, meta, labels and the `match` and `options` lines are synthetic: they get no token. A finding in rendered `match` or `options` text lands on the YAML value it came from (`match.group_by.1`); one on a label lands on the key; one in the header or meta is a platform constraint instead, except a syntax error, which moves to the nearest text the author wrote. The meta is generated without ATT&CK tactics: the engine checks the body.

The pinned opentide's catalogue does not have the `google_secops` block yet: until the Tide catalogue is regenerated from opentide's models, the schema check reports the block as unknown.

## Editor features

`crates/opentide-yaral/src/editor.rs`, in `.yaral` files and inside the block's sections and hunts:

| Feature | What it does |
|---------|--------------|
| Hover | A UDM path segment shows its path, type, `repeated`, deprecation, Google's description and an enum's values; a function its signature, description, result type, availability and Google's page; the platform outcome names (`$risk_score`, `$risk_entity_to_score`, `$suppression_key`); a reference list |
| Completion | Fields after `$e.` (and `udm`, `graph`, `detection` at the root) or a bare path; enum values after `metadata.event_type =` (quoted, or inside the quotes); a namespace's functions after `strings.`; elsewhere section labels, keywords, namespaces, aggregations and the text's variables |
| Signature help | The function whose parentheses hold the cursor, with the active argument |

## Corpus and verdicts

- `testdata/corpus/yaral/`: one valid and one invalid fixture per production (`crates/opentide-syntax/tests/corpus_gate.rs`).
- `testdata/conformance/external/yaral/`: 79 community rules from chronicle/detection-rules (Apache-2.0), unmodified, each with a `.broken.` twin (`scripts/sync_yaral_corpus.py`, `crates/opentide-yaral/tests/external_corpus.rs`). Every public file parses and has no error but one listed exception; every twin has an error. Over the whole `rules/community` tree (410 rules) the grammar parses every rule, and the engine reports an error on one: a meta description with `\T` and `\L` escapes, which yara-l-1.0 refuses.
- `testdata/conformance/specifications-google-secops/`: the spec's fixtures and golden texts, CC BY 4.0.
