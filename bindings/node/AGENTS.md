# opentide-node (bindings/node) — agent guide

The npm package `@opentide/opentide` (UC-5.3, #838; ADR 0006): the opentide SDK and the
`opentide` command line for Node.js, one package as on PyPI. The Rust crate `opentide-node`
(`publish = false`) binds the facade, `opentide` with its `cli` feature, with napi-rs 3; the
package's `opentide` bin calls its `main(argv)` in Node's process.

## Place

bindings (`xtask/layers.toml`): depends on the facade alone (ADR 0005); nothing depends on it.
It copies the workspace's lint table with `unsafe_code = "deny"` instead of inheriting `forbid`,
because napi-derive's registration (a `ctor` static constructor per `#[napi]` item) carries
`#[allow(unsafe_code)]`; it writes no `unsafe` of its own (`docs/internal/unsafe.md`,
`xtask/tests/lint_policy.rs`).

## Layout

| Path | What |
| --- | --- |
| `Cargo.toml`, `build.rs`, `src/lib.rs` | The binding: `Workspace` and its methods, `runJson`, `main`, `VERSION` |
| `index.js`, `index.d.ts` | The loader and the TypeScript declarations, generated by `npm run build` (napi-rs) and committed; CI's `node` job fails when a build changes them |
| `cli.js` | The `opentide` bin: `process.exit(main(process.argv.slice(2)))` |
| `build.mjs` | `napi build --platform` for this machine, with `OPENTIDE_VERSION` the package's version unless set |
| `npm/<platform>/` | The native package of each of the six targets (`napi create-npm-dirs`; no musl, the maintainer's decision), the package's optional dependencies; CI builds linux-x64-gnu, the release train (`publish.yml`) all six |
| `alias/` | The `opentide` package: depends on `@opentide/opentide`, re-exports it, the same bin |
| `test/` | `node --test`: the SDK against `runJson`, the bin (exit codes, Ctrl-C), the packages, `docs/sdk/typescript.md`'s snippets; `consumer.ts` type-checks against `index.d.ts` |

## Rules

- **Thin.** Each function converts its arguments, calls one facade function and converts the
  result. Logic belongs in the facade or below it.
- **Documents keep the CLI's key order.** Serialise the facade's types (field order), or hand a
  `Document`'s text to `JSON.parse`; never a `serde_json::Value`, whose keys come sorted.
- **Errors carry a code.** A failed call throws an `Error` whose `code` is the facade's
  `Error::code` (or `usage_invalid_choice` for an option the CLI would refuse).
- **Declarations.** After changing `src/lib.rs`, run `npm run build` and commit `index.js` and
  `index.d.ts`; update `docs/sdk/typescript.md` and `test/consumer.ts` with the API.
- **Versions.** The package, the six native packages and the alias share one version, the
  product's, which the release train writes in (`scripts/engine/release.py npm-version`, UC-5.5)
  and checks (`release.py lockstep --npm`); `test/packages.test.mjs` checks the tree's. Nothing
  here is published by hand: `.github/workflows/publish.yml` packs and publishes them with
  provenance.

## Verify

```bash
cargo clippy -p opentide-node --all-targets -- -D warnings
cargo test -p opentide-node
cd bindings/node && npm ci && npm run build && npm test
cargo xtask golden check --runner node     # after `uv sync --group dev`
```
